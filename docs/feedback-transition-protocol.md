# 피드백 뒤 선택 유지·전환 지표의 준비 계획

작성일: 2026-10-15 (Asia/Seoul). 기존 인간 자료 의미·원본 감사를 보존하는 후속 설계다. 원자료 구조와 가용 범위는 이미 확인했으므로 탐색적 측정 준비로 분류한다. 실제 행동 집계는 이 문서와 코드·설정·원자료·시험의 고정 및 아래 게이트 확인 이후에만 허용한다.

## 먼저 쉽게 설명하면

좋은 결과를 받은 뒤 같은 카드를 다시 고르는지, 좋지 않은 결과를 받은 뒤 다른 카드로 바꾸는지 살펴볼 수 있다. 다만 여기서 ‘좋은 결과’는 **실제로 받은 피드백**이지 정답을 골랐다는 뜻이 아니다. 확률적인 과제에서는 유리한 카드를 골라도 좋지 않은 결과를 받을 수 있다.

화면의 왼쪽 카드가 다음 문제에서는 오른쪽으로 옮겨졌다면 왼쪽을 계속 눌렀는지만 세어서는 안 된다. 먼저 어느 기록이 같은 카드·선택지를 뜻하는지 확인한다. 정보 요청을 한 번 끼워 넣었을 때 그 시행을 지우고 앞뒤 선택을 바로 이어 붙이는 것도 허용하지 않는다. 이번 작업의 목적은 사람과 모델에 **같은 뜻의 측정법을 적용할 준비**다. 높은 유지율이 더 좋은 학습이라는 결론을 미리 정하지 않는다.

## 두 단계와 실제 계산의 범위

1. **과제 의미와 변환 확인:** 원 저자 자료·논문·실험/변환 코드에서 카드 선택, 정보 요청, 실제 결과, 상태와 반전, 시행 구획의 뜻을 확인한다. 근거가 있는 필드만 공통 형식으로 옮긴다.
2. **지표의 합성 검증:** 인공 자료로 아래 분모·분자·제외 규칙을 검증한다. 의미·변환·동결 게이트가 모두 통과하면 고정 범위에서 기술적 실제 집계를 별도로 등록해 실행할 수 있다. 통과하지 못하면 공통 형식과 합성 검증까지를 결과로 남긴다.

실제 집계를 하더라도 자료별·기록별 정해진 횟수와 조건부 비율만 계산한다. 인간 집단 간 차이, 사람/모델 간 차이, 학습 곡선·반전 비용·정답률·교육 효과·RL 모형 적합·유사성 검정은 이번 범위가 아니다. 실제 값이 비슷한 범위나 모델을 나중에 선택하지 않는다.

## 먼저 확인해야 할 과제 의미

| 필드 | 통과에 필요한 근거 | 아직 부족한 근거 |
|---|---|---|
| 지속적인 선택지 정체성 | 실제 선택 코드가 같은 카드·선택지에 대응한다는 원 코드·과제 정의 | 같은 숫자 코드, 같은 화면 좌우, 같은 파일 열 이름 |
| 실제 피드백 | 그 선택 후 실제 관측한 결과의 코드와 의미 | 예정 보상 확률, 정오 코드, 모델의 선택 확률 |
| 정보 요청·무응답 | 별도 행동과 결측의 원 코드, 해당 시행의 보존 | 정보를 요청한 시행을 삭제한 배열 |
| 시행 인접성 | 원 시행 번호와 순서, 누락·재시작·반복 블록 처리 | 유효 응답만 남긴 다음의 새 행 번호 |
| 과제·단계·반전 | 원 상태의 뜻과 시점, 어느 경계 뒤 새 규칙이 적용되는지 | 받은 보상이 달라졌다는 사실, 선택이 바뀌었다는 사실 |
| 모델의 실제 선택 | 실제 샘플링한 행동과 제시 입력, 행동을 지속적인 선택지로 바꾸는 근거 | sigmoid 확률, 기대 행동 또는 정답 선택 확률만 있는 기록 |

원본 값이 가공본과 정확히 일치했다는 사실은 이 의미 확인을 대신하지 않는다. 특히 OpenNeuro의 미해결 선택·기대 코드를 이번 지표에 자동으로 재사용하지 않는다. Marković 자료에서도 상태·카드 정의를 원 근거로 확인한다. `R`의 시행별 실제 결과가 바뀌었다는 이유만으로 반전 경계를 만들지 않는다.

사람의 카드 A/B와 모델의 두 선택지를 모두 `0/1`로 바꿀 수 있어도 같은 자극·노력·경험이라는 뜻은 아니다. 모델에서 화면 좌우가 매번 바뀌면 제시 입력을 함께 사용해 선택한 수량·선택지의 정체성을 복원해야 한다. 그 근거가 없으면 모델 지표는 보류한다.

## 공통 형식의 최소 요구사항

각 기록은 원래의 의사결정 시행 위치를 한 행씩 보존한다. 정보 요청·무응답도 남기며 원 시행을 합성하지 않는다. 필수 정보는 다음과 같다.

- 불투명한 기록 ID, 자료 종류, 원 파일·코드 버전·SHA-256, 원 행 또는 원 배열 위치.
- 과제·단계 ID와 원 시행 번호, 선택 `0/1/정보 요청/결측` 및 원 코드.
- 시행의 실제 피드백 `0/1/기타/결측`과 원 코드. 정보 요청 결과 `2/3`을 금전 보상이나 이진 피드백으로 바꾸지 않는다.
- 다음 시행 직전의 과제·단계·반전 경계와 근거. 모르는 경계를 ‘없음’으로 채우지 않는다.
- 학습용 시행인지 별도 평가인지, 모델이면 실제 선택 로그인지, 시행이 원 순서에서 인접한지.

필요한 의미 또는 경계 정보가 없으면 그 필드가 필요한 지표는 `준비 미달`로 남긴다. 구현이 자동으로 추정한 값과 원 근거로 확인한 값을 구분한다. 모델의 출력 확률을 실제 선택 `0/1`로 임계값 처리해 대체하지 않는다. 별도 평가 probe를 학습 중 실제 선택처럼 이어 붙이지 않는다.

인간 대상 범위는 원본 변환이 검증된 Main 25행으로 한정한다. 미검증 49행은 대상 목록에서 상태를 보존하되 원본이 있는 것처럼 행동 기록을 만들지 않는다. 고정된 25행 모두를 사용하며 실제 결과를 보고 일부 기록을 고르지 않는다. 모델의 대상 실험·조건·시드·분기는 실제 집계 전에 별도 설정에 명시한다.

이번 인간 과제의 사전 고정 구획은 시행 1–800의 `initial`과 시행 801–1000의 `transfer`다. 800→801에서는 반전 간격의 분포 규칙이 달라지므로 원 상태 `S`가 같은 경우에도 `phase_boundary`로 제외한다. 설정의 `human.regime_boundary_after_trial=800`에 고정한다. `S`의 변화에 따른 `state_boundary`와 별도 사유이며 둘이 겹쳐도 총 제외에서는 한 쌍이다. 실제 지표 집계 전에 문헌 근거로 고정한 정의다.

선택지 정체성은 확인한 원 코드·변수의 의미에 근거한 범위로 한정한다. 공개된 코드가 2018년 실제 실험에서 실행된 정확한 버전과 동일한지는 확인되지 않았다는 제한을 결과에도 남긴다. 기록에 없는 시행별 위치·화면 로그를 새로 복원했다고 주장하지 않는다.

## 주 지표의 고정 분모

후보는 같은 원 기록에서 바로 이웃한 원 시행 `t, t+1`이다. 길이가 N인 완전한 한 기록은 최대 N−1개 후보를 가진다. 마지막 시행을 다음 기록의 첫 시행과 연결하지 않는다. 정보 요청이나 결측을 건너뛰어 `t, t+2`를 연결하지 않는다.

주 정의의 유효 쌍은 아래 조건을 모두 만족해야 한다.

1. `t`와 `t+1` 모두 같은 지속적인 두 선택지 중 하나를 실제로 선택했다.
2. `t`의 실제 피드백이 확인된 이진 `0/1`이다.
3. 원 시행 순서에서 인접하며 같은 과제·단계에 속한다.
4. 두 시행 사이에 확인된 반전 경계가 없다.
5. 두 시행 모두 등록한 학습 선택 기록이며 별도 probe나 기대 행동 기록이 아니다.

다음 시행의 피드백은 이 쌍의 분모 조건이 아니다. `t+1`의 선택이 확인되어 있다면 그 뒤 피드백이 결측이라는 이유만으로 현재 쌍을 빼지 않는다. 반대로 `t`의 피드백이 없으면 쌍을 제외한다.

반전은 원 과제에서 확인한 상태·적용 시점을 사용한다. 주 정의에서는 반전을 가로지르는 한 쌍을 제외한다. 단계 경계를 넘어 잇거나 반전 부근을 임의로 더 넓게 삭제하지 않는다. 실제 집계를 보고 반전 횡단 쌍을 포함하는 정의로 바꾸지 않는다. 별도의 민감도 정의를 추가하려면 먼저 새 범위와 해석을 등록한다.

## 분자·분모와 보고값

실제 피드백 `f=0,1` 각각에 대해 다음을 기록별로 계산한다.

| 값 | 고정 정의 |
|---|---|
| `D_f` | 유효 쌍 중 `t`의 실제 피드백이 f인 쌍 수 |
| `S_f` | 그중 다음 선택이 같은 선택지인 쌍 수 |
| `X_f` | 그중 다음 선택이 다른 선택지인 쌍 수. `D_f−S_f`와 같아야 함 |
| 유지 비율 | `S_f / D_f`; 분모가 0이면 결측과 `분모 없음`으로 표시 |
| 전환 비율 | `X_f / D_f`; 분모가 0이면 동일하게 미정의 |

분모가 0일 때 비율을 0 또는 1로 채우지 않는다. 합계 검산은 `S_f+X_f=D_f`, `D_0+D_1=유효 쌍 수`다. 주 출력은 기록별 수치다. 전체 횟수를 합산한 기술 표를 함께 낼 경우에는 ‘유효 쌍 수에 비례해 가중된 합산’이라고 명시하며 기록별 비율의 평균이나 평균적인 사람의 특성과 혼동하지 않는다. regular/irregular 등의 집단 차이와 사람/모델 차이는 계산하지 않는다.

조건부 유지율은 피드백의 인과적 효과가 아니다. 선택한 카드·과거 경험·잠재 상태가 피드백과 다음 선택 모두에 관련될 수 있다. 정보 요청·무응답 제외는 특정 경험의 쌍을 더 많이 제외할 수 있으므로 전체 행동의 대표값이라고 가정하지 않는다. 비율만 제시하지 않고 분자·분모와 제외 내역을 함께 남긴다.

이번 모델 phase2에서는 `reward == int(choice == smaller)`로 보상과 현재 선택지가 완전히 결합되어 있다. 따라서 모델의 `stay | reward=1`은 작은 수량을 고른 뒤 작은 수량을 유지하는 비율이고, `stay | reward=0`은 큰 수량을 고른 뒤 큰 수량을 유지하는 비율이다. **보상 자체에 대한 반응과 특정 선택지를 계속 고르는 경향을 이 지표만으로 분리할 수 없다.** 작은 수량을 자주 고르는 정책만으로도 두 조건의 유지율이 달라질 수 있다.

사람 과제에서는 같은 카드에서도 확률적으로 금전 이득·손실이 발생한다. 사람의 피드백 `0`은 금전 손실을 나타내지만 모델의 `0`은 무보상이며 손실이라고 부르지 않는다. 이 과제 차이를 숫자 코드 `0/1`로 숨기지 않는다. 사람과 모델의 지표가 다르더라도 이를 종간 학습 능력이나 보상 민감도의 차이로 해석하지 않는다.

## 제외 기록과 중복 집계 방지

모든 원 인접 후보에 원 위치·채택 여부·사유 목록을 남긴다. 정보 요청, 현재/다음 선택 결측, 현재 피드백 결측·비이진, 원 시행 간격, 과제·단계·반전 경계, probe·비실제 선택을 구분한다. 하나의 쌍에 이유가 여러 개면 모두 남기되 총 제외 쌍 수에는 한 번만 센다.

`후보 쌍 수 = 유효 쌍 수 + 제외 쌍 수`를 확인한다. 사유별 건수의 합은 중복 사유 때문에 총 제외보다 클 수 있다. 알 수 없는 코드·중복 시행 키·원 순서 역행 등 입력 무결성 오류는 임의 제외로 숨기지 않고 검사 실패로 남긴다. 무응답을 오답이나 특정 카드로 바꾸지 않는다.

모델의 공유 학습 prefix를 여러 분기에서 재사용했다면 분기의 원 계보를 보존한다. 복제된 prefix를 독립 시행으로 여러 번 합산하지 않는다. 한 시드의 여러 조건·분기를 독립적인 생물학적 개체로 세지 않는다. 사람 기록과 모델 시드는 별도 단위이며 하나의 표본으로 합쳐 유의성 검정을 하지 않는다.

## 합성 테스트와 동결

실제 행동 집계 전 다음을 인공 자료로 확인한다.

- 각 피드백 뒤 유지·전환이 모두 있는 예, 전부 유지 또는 전부 전환인 예, 분모 0인 예.
- 정보 요청·무응답을 사이에 두어도 앞뒤 시행을 연결하지 않음.
- 현재 피드백 결측은 제외하고 다음 피드백 결측만 있는 쌍은 유지함.
- 선택지는 같지만 화면 좌우가 바뀐 경우, 좌우는 같지만 선택지가 바뀐 경우.
- 반전·단계·과제 경계, 원 시행 간격과 probe를 지정된 규칙대로 처리함.
- 사유가 겹치는 쌍의 사유 목록 보존 및 총 제외의 중복 방지.
- 원본과 입력 불변, 원 위치 추적, 공유 prefix 계보와 분기 보존.
- 미지 코드·비정수 시행 키·중복·역행·누락된 필수 의미 근거의 명시적 거부.
- 원자료·코드·설정·프로토콜 해시 변경과 기존 출력 덮어쓰기를 거부함.

실제 집계를 허용할 때에는 선택지 정체성·피드백·상태 근거, 전체 대상 목록, canonical 변환, 분모·분자·경계 정의, 코드·시험·원본의 해시와 Git 버전을 먼저 고정한다. 독립 검산은 주 변환·집계 함수를 부르지 않고 고정 입력에서 후보·제외·분자·분모를 다시 확인한다. 실행 시각과 환경·재현 명령도 남긴다.

## 재현 명령과 출력 보호

완료 뒤에는 `feedback-transition-v1` 태그의 별도 checkout에서 저장소 루트를 작업 경로로 사용한다. Python 3.12 가상환경에 `requirements-lock.txt`와 `requirements-human-candidate-audit.txt`의 고정 의존성을 설치한다. `src/drosolearn/__init__.py`를 포함한 코드·프로토콜·테스트·환경 명세는 등록의 동결 목록과 같아야 한다. 새 버전의 파일로 이전 등록을 덮어쓰지 않는다.

아래 `../DrosoLearn-osf-origin-cache`는 앞 원본 감사에서 준비한 고정 외부 캐시다. 캐시가 없다면 [원본 재현 프로토콜](human-osf-origin-protocol.md)의 고정 버전·해시 복구 절차를 먼저 사용한다. 실제 경로가 다르면 세 명령에서 같은 외부 캐시 경로로 바꾼다. 각 출력은 아직 존재하지 않는 새 경로여야 한다.

```powershell
.\.venv\Scripts\python.exe scripts/run_feedback_transition.py register --human-cache ../DrosoLearn-osf-origin-cache --out results/registration_FEEDBACK_NEW.json
.\.venv\Scripts\python.exe scripts/run_feedback_transition.py run --human-cache ../DrosoLearn-osf-origin-cache --registration results/registration_FEEDBACK_NEW.json --out results/FEEDBACK_NEW
.\.venv\Scripts\python.exe scripts/verify_feedback_transition.py --registration results/registration_FEEDBACK_NEW.json --result-dir results/FEEDBACK_NEW --human-cache ../DrosoLearn-osf-origin-cache --out results/FEEDBACK_NEW_VERIFICATION.json
```

등록과 독립 검증의 `--out`은 새 JSON 파일이고, 주 실행의 `--out`은 새 디렉터리다. 주 실행에는 `--registration`이 필요하다. 등록은 부모 구조 게이트와 입력 해시를 확인하지만 새 유지·전환 지표를 집계하지 않는다. 실제 최초 집계는 등록·원격 원바이트 확인 뒤에 진행하며, 결과의 실패·예외도 새 경로에 보존한다.

## 종료와 해석 게이트

| 상태 | 허용되는 결과 | 보류할 결과 |
|---|---|---|
| 선택지 또는 상태 의미 미확정 | 근거 목록·한계·공통 형식 초안·합성 시험 | 해당 자료의 실제 지표 |
| 사람 자료만 의미·변환 확인 | 그 자료의 별도 등록 후 기록별 기술 집계 | 모델 값을 추정해 만든 비교 |
| 모델 자료만 의미·실제 행동 확인 | 그 자료의 별도 등록 후 기록별 기술 집계 | 실제 행동이 없는 사람 자료의 보완 추정 |
| 양쪽 의미·변환·분모 확인 | 동일 정의의 측정 가능 범위와 기술 결과 | 사전 가설 없는 집단 비교·유사성·학습효과 검정 |

기술적 집계가 가능해져도 사람과 모델은 자극, 정보 요청 행동, 확률적 피드백, 선택 정책, 연습 예산과 시간에서 다르다. 사람의 두 카드와 모델의 인공 수량은 동일한 수학 과제가 아니다. 겹치는 인접 쌍과 연속 행동은 서로 독립적이지 않으므로 각 쌍을 독립 표본으로 가정한 신뢰구간·유의성 검정을 추가하지 않는다.

자료 준비·기술 지표의 통과는 Level 4 또는 Level 5의 증거가 아니다. 다음 비교 가설은 과제 차이와 대안 설명, 단순 모델·대조 조건, 평가 기준을 별도 계획으로 고정한 뒤 검토한다. 기존 DrosoMem과 완료한 코드·자료·설정·등록·불일치·실패·결과는 변경하지 않는다.
