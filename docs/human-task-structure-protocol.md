# 사람 카드 과제 구조의 후속 검증

작성일: 2026-10-15 (Asia/Seoul). 연구 ID `human_task_structure_v1`.

카드가 자리를 바꿔도 같은 카드로 기록되는지, 결과가 나쁜 것이 오답과 같은 뜻인지 먼저 구분한다. 이는 학습 성적을 재는 단계가 아니라 **기록의 뜻과 과제 구획을 확인하는 단계**다. 원 논문과 코드 근거는 `human-task-structure-sources.md`에 분리한다. 공개 코드가 과거 각 기록에 실제 실행된 정확한 버전이라는 증명은 없다.

## 실행 전에 고정하는 범위

기존 `human_osf_origin_v1`에서 원본·가공본의 75,000개 값이 일치한 Main 25개 원본을 모두 사용한다. 원본 미대응 49행은 그대로 미검증이다. 원본은 외부 캐시에 두고 기존 manifest의 파일 ID·버전·크기·SHA-256을 확인한다. 25개를 결과에 따라 선택하거나 바꾸지 않는다. 구조와 원본 변환을 이미 조사한 탐색적 후속 감사이며 눈가림 확증 연구로 표시하지 않는다.

등록에서는 해시만 읽는다. 등록·소스·원자료 목록을 private Git에 공개한 뒤 처음으로 다음 구조 관계와 S 전환 구획을 계산한다. 성공 기준을 결과에 맞춰 바꾸지 않는다.

1. A와 C는 1×1000, S는 1000×1, R은 1000×2인 실수 수치 배열이다. 무한대는 허용하지 않는다.
2. A는 1/2/3/NaN, C는 0/1/NaN, S는 1/2, R은 −1/+1이다. 기존 원본 검증에서 확인한 고정 코드 범위를 재검사한다.
3. A가 카드 1/2인 모든 위치에서 C가 유한하고 `C == int(A == S)`다. 이는 정답률을 계산하는 것이 아니라 원 변수들의 코드 관계를 검사한다.
4. A가 정보 요청 3 또는 결측인 위치의 C는 NaN으로 보존된다.
5. 기존 formatter의 regular/irregular 구분 안에서 S/R 궤적이 완전히 같다. 폴더 이름이나 공개 과제 코드의 다른 배정 규칙으로 그룹을 새로 정하지 않는다.
6. 반전은 실제 받은 R 값의 변화로 추정하지 않는다. S가 원 시행 i에서 바뀌면 i를 새 상태 첫 시행으로 기록한다. 상태별 구간 시작·길이와 궤적 해시를 보존한다. 상태 전환 목록은 선택 반응이나 반전 비용이 아니다.

각 원본의 실패·예외를 보존한다. 하나라도 위 기준을 충족하지 못하면 사람 행동 지표 게이트는 닫는다. 임의 보정·행 이동·코드 치환·참가자 제외로 통과시키지 않는다. 모든 구조 검사에 통과해도 허용되는 후속은 **source-coded 카드 선택의 별도 등록된 기술 집계**뿐이다. 정확한 과거 실행판, 사람과 모델의 같은 경험 또는 인간 학습 유사성이 입증되는 것은 아니다.

## 원 코드의 한계

공개 코드와 원본 수집 시기의 차이, 피드백 노출 시간의 문헌/코드 차이, 무응답 코드 경로의 R 선형 인덱싱 문제를 원문과 함께 남긴다. 이것만으로 실제 자료가 손상됐다고 주장하지 않는다. `random_lr`는 카드 좌우 배치이며 정보 요청 가능 여부가 아니다. 정보 요청 결과 2/3은 상태 정보이지 돈 보상 크기가 아니다. R은 선택별 잠재 결과 표이고 실제 금전 피드백은 해당 시행의 실제 A로 선택한 칸이다.

## 재현과 보호

`scripts/audit_human_task_structure.py register --cache ../EXTERNAL_CACHE --out results/registration_TASK_NEW.json`으로 등록하고, 같은 도구의 `run --registration ... --cache ... --out results/TASK_NEW.json`으로 검사한다. 저장소 루트의 고정 Python 환경을 사용한다. 예시 캐시는 기존 OSF 원본 캐시 구조를 가진 저장소 밖 경로다. 모든 출력은 새 파일만 허용한다.

합성 시험은 모양·코드 오류, C의 단일 불일치와 결측, 정보 요청, 상태 전환의 1기반 위치, 궤적 변조, 경로 탈출과 덮어쓰기를 검사한다. 원자료는 시험에 사용하지 않는다. 완료 후 별도 독립 산술 검산으로 원본 A/C/S/R에서 관계·구획·조건 내 동일성을 다시 확인한다. 원문·설정·코드·시험·부모 검증 결과의 해시, Git 버전, UTC 실행 시각과 환경을 기록한다. 기존 연구의 파일과 결과는 변경하지 않는다.
