작성일: 2026-10-20 (Asia/Seoul). 연구 ID는 `cone_frontier_v1`이다.
완료 기준선은 `normalization-loss-v1`, commit
`f1ada01a904283a1036b4dc77b10fb3882194750`다. 새 학습을 실행하지 않고 저장된

독립 행동 가설 검정이라고 부르지 않는다.

## 쉽게 설명하면

앞선 방식은 방해를 지우면서도 나머지 영향의 비율을 그대로 유지하려 했다. 그 조건을 모두
맞추려면 크게 움직여야 했고, 한 번에 움직일 길이를 줄이자 자기 수정과 도움도 작아졌다.

이번 질문은 **“방해하지 않는다는 조건은 지키되, 도움의 비율까지 똑같이 유지할 필요가
있을까?”**다. 같은 길이 안에서 방향을 다시 고른다. 자기 답을 가장 잘 고치는 방향과,
자기 수정·알려진 도움을 함께 고려하는 방향을 따로 계산한다. 두 목표는 서로 충돌할 수 있다.
한쪽에 최적인 방향을 두 가지 모두에 최적이라고 부르지 않는다.

이는 저장된 한 번의 수정을 다른 방향으로 보냈다면 생기는 **선택 전 점수 변화**다. 새
방향으로 계속 학습했다면 정답률이 얼마가 될지는 계산하지 않는다. 방향을 바꾸면 이후
확률·선택·보상도 바뀌므로, 저장된 경로를 새 학습 결과처럼 합쳐 보고하지 않는다.

## 정보 조건: 실제 관측과 정답표 참고

입력별 단위 특징 행을 D, 공유 영향 행렬을 `M=D D^T`, 현재 문제를 i라 한다. 부모가 실제
획득한 보상 부호 기록 `known_after`를 k로 쓴다. 현재 시행의 Go 보상은 부모 규칙처럼
기록한 뒤 사용할 수 있다. NoGo의 0 보상은 숨은 Go 보상이나 정답 부호를 알려주지 않는다.
아직 모르는 부호 0을 평가용 정답으로 채우지 않는다.

- **관측 기반 조건:** k에 실제 저장된 `known_after`만 전달한다. 현재 source의 부호도
  모르고 있으면 다른 문제에 대한 안전 부호를 추론하지 않는다.
- **전체 정보 참고:** 별도의 전체 정답 부호 `y=[+1,+1,-1,-1]`를 사용한다. 이는 숨은
  부호를 가진 진단 참고이며, 실제 보상만 쓰는 방법을 대신하지 않는다.

최적화는 실제 `g!=0`인 Go 갱신에만 수행한다. 이 시행은 현재 source의 부호가 실제 보상으로
이미 밝혀져 있다. NoGo/g=0 시행은 모든 후보의 영향·점수 변화·이동 길이를 정확히 0으로
저장하고 최적화를 호출하지 않는다. 이 경우 최적화 case index는 −1이다.

평가자는 두 조건의 결과를 실제 정답 방향으로 측정할 수 있다. 이때 쓴 y는 관측 기반 방향
선택기에 전달하지 않는다. 관측 기반 방향은 **이미 아는 문제에서만** 방해 금지를 보장한다.
미관측 문제에는 새 방해가 생길 수도 있으므로, 그 실제 방해를 평가 전용 지표로 따로 남긴다.

전체 정보 조건은 안전 조건이 더 많으므로 항상 자기 수정량이 더 크다고 가정하지 않는다.
각 조건의 최댓값은 그 조건에 정해진 안전 범위 안에서의 상한이다. 부분 관측의 더 큰 점수가
숨은 문제를 방해하는 대가일 수 있다. 실제 관측 네 칸을 모두 채운 전후 구간도 나누되, 시점·
보상 경험·출력 상태가 함께 달라지는 기술 비교이며 정보 획득만의 인과효과가 아니다.

## 같은 이동 상한과 완화한 조건

대안 방향 w는 다음 조건을 만족한다.

```text
||w||_2 <= 1
(k[i] * k[j] * D[j]) @ w >= 0     k[i], k[j]가 둘 다 알려진 모든 j
```

source 자신도 알려져 있으면 제약에 포함한다. 즉 자기 답을 오답 쪽으로 바꾸지 않는다.
알려진 다른 문제도 오답 쪽으로 움직이지 않도록 한다. 부호가 알려진 목적지가 최대 4개여서
선형 부등식도 최대 4개다. 모르는 destination에는 제약을 몰래 추가하지 않는다.

앞선 선택 억제는 방해 항을 0으로 만든 뒤 다른 모든 raw 영향의 크기·비율을 고정하고
정규화했다. 이번에는 **영향의 비율과 미관측 영향의 크기를 고정하지 않는다.** 알려진 도움은
음수가 되지 않으면 크기가 바뀔 수 있다. 알려진 기존 방해도 음수 대신 0 또는 양수가 될 수
있다. 따라서 같은 문제를 더 잘 푼다고 말하려면 완화한 조건을 함께 밝힌다.

실제 저장된 갱신 스칼라는 다음과 같다.

```text
g = .1 * (actual_action - stored_probability_go) * obtained_reward
candidate_delta_head = g * w
candidate_margin_delta[j] = y[j] * g * (D[j] @ w)
```

`||w||<=1`이므로 동일 시행의 부모와 같은 `abs(g)` 이동 상한 안이다. NoGo이면 g=0이므로
대안 점수 변화도 0이다. 비영 Go 갱신에서는 g의 부호가 source의 실제 정답 부호와 같으므로,
실제 관측이 올바르게 저장되어 있다면 위 제약이 관측 문제의 정답 정렬 점수를 음수가 되지
않게 한다. 스칼라·확률·행동·관측 기록은 새 방향으로 재계산하지 않는다.

이 비교는 같은 저장 갱신의 길이 상한을 맞춘다. 새 최적화 계산, 별도 관측 기억, 정보 접근,
실현된 총 이동 경로, 장시간 학습 자원이 모두 같다는 뜻은 아니다. 공유 방향이 알려진
방해를 포함하면 새 안전 영역 밖에 있을 수 있으므로, 안전 영역의 최댓값을 공유 방향까지
포함한 무조건적인 상한이라고 부르지 않는다.

## 사전에 정한 두 목적

현재 정보로 판단한 기존 공유 도움 집합은 다음과 같다.

```text
H = {j != i : k[i] != 0, k[j] != 0,
                 k[i]*k[j]*M[i,j] > 1e-8}
```

단위 특징으로 두 목적의 단위를 맞춘다.

1. `own`: `c=D[i]`. 안전한 방향 중 source 점수의 증가를 가장 크게 한다.
2. `balanced`: H가 비어 있으면 `c=D[i]`. 아니면
   `c=.5*D[i] + .5*mean(k[i]*k[j]*D[j] for j in H)`.
   자기 수정과 기존의 알려진 도움 평균에 같은 목적 가중치를 준다.

각각 `c @ w`를 최대화한다. 도움의 합 대신 평균을 쓰므로 알려진 도움 개수가 늘었다는
이유만으로 총 목적 가중치가 커지지 않는다. 실제 도움이 되는지 판단할 때에는 합·평균의
차이를 숨기지 않는다. H는 실제 평가용 모든 정답을 보지 않고 해당 정보 조건으로만 만든다.
추가 가중치 검색이나 유리한 조건별 목적 변경은 하지 않는다.

`own`이 자기 수정에 최적이어도 도움의 양이 가장 크다는 뜻은 아니다. 균형 목적이 자기 수정과
도움 둘 다 기존보다 크다는 보장도 없다. 두 양과 방해를 나란히 측정한다. 이 두 목적은 안전한
방향의 모든 가능한 절충을 그리는 완전한 Pareto 곡선이 아니라, 사전에 고른 두 지지점이다.

## 최적성 검산: 방향을 찾았다는 주장과 증거

부등식 행렬을 A라 하면 안전한 방향은 `A w>=0`인 원뿔과 단위 공의 교집합이다. 목적 c를
이 원뿔에 투영한 p를 구하고, p가 비영이면 `w=p/||p||`를 쓴다. 원뿔은 동차 제약으로
이루어져 정규화해도 부호 조건이 바뀌지 않는다. p가 수치상 0이면 w도 0이며 억지로 나누지
않는다.

제약이 최대 4개이므로 활성 제약 부분집합을 최대 16개 전부 열거한다. 각 부분집합의 SVD로
후보를 구하되 rank cutoff `1e-12`는 제약 행 자체의 특이값에 적용한다. 제곱 Gram 행렬에
같은 cutoff를 적용해 살아 있는 작은 방향을 조기에 지우지 않는다. 음의 승수는 허용 오차
안의 반올림만 0으로 정리하고 그 변화와 잔차를 기록한다. 수치적 0 정리 역시
`128*machine_epsilon*||c||` 이내이며 별도 잔차로 남긴다.

최종 후보는 다음 독립 검산 가능한 증거를 가져야 한다.

```text
p = c + A.T @ lambda
lambda >= 0
A @ p >= 0
lambda * (A @ p) = 0
```

따라서 안전하고 길이가 1 이하인 어떤 z에도

```text
c @ z = p @ z - lambda @ (A @ z) <= ||p||
```

이며 선택한 w가 그 상한에 도달한다. 반올림된 투영의 잔차만으로 상한을 주장하지 않도록,
반환된 비음수 승수로 `dual_vector=c+A.T@lambda`,
`dual_upper_bound=||dual_vector||`도 별도로 계산한다. 이 쌍대 상한과 달성값의 차이가
허용 오차 이하여야 한다. 이는 해당 목적·정보·제약 안의 **한 번 수정에 대한 수치 최적성
증거**다. 모든 학습법이나 모든 인지 과제의 한계를 증명하지 않는다.

유한성, 원래·정규화된 방향의 제약 위반, 승수 부호, 정류 조건, 상보성, 활성 등식, 길이 위반,
목적 상한과 달성값의 차이, 반올림 정리 잔차가 모두 고정 허용 오차 `1e-8` 이하여야 한다.
실패하면 기록하고 해석을 중단한다. 제약·수치 문턱·시드·학습 예산을 바꿔 통과시키지 않는다.

## 측정과 비교의 의미

6개 조건의 모든 저장 시행에서 원래 방향과 각 대안 방향에 같은 g를 곱한다. 후보 순서는
`parent_feedback, shared_reference, isolated_reference, observed_own,
observed_balanced, oracle_own, oracle_balanced`로 고정한다. 공유·전체 억제 참고도
**같은 feedback 경로의 g와 관측 상태**에 적용한다. 원래 공유·전체 억제 학습자가 실제로
선택하고 보상을 얻은 별도 경로의 성적이 아니다.

자기 수정, 기존
공유 도움 destination, 기존 공유 방해 destination, 수치 중립 destination, 현재 미관측
destination을 구분한다. 도움·방해 분류의 실제 정답은 평가용이며, 새 방향의 입력 정보가 아니다.
수치 중립 문턱 안의 작은 질량도 실제 합계에서 버리지 않는다.

각 목적의 달성값·상한, 자기 점수 변화, 원래 공유 도움 집합에 남긴 양수 점수, **모든 다른
문제**에서 발생한 음수 점수 절댓값, 미관측 문제의 실제 방해, 방향 길이, 알려진 안전 조건
위반과 수치 잔차를 보존한다. 원래 도움이던 문제에 새 방해가 생겨도 전체 방해 질량에 포함한다.
반대로 원래 방해·중립 목적지에 새로 생긴 도움은 기존 도움 집합 지표와는 별개이며 전체
signed 점수에 포함된다. `자기+기존 도움−방해=전체 점수`라고 가정하지 않는다. 모든
조건·시드의 `all, partial, full` 관측 구간을 남긴다. full은 해당 시행의 `known_after`
네 칸이 모두 비영인 경우이며 마지막 발견 시행도 포함한다. 정답표 참고의 구간도 별도 특권
정보가 아닌 실제 관측표로 나눈다.

자기 수정·도움 보존율의 분모는 같은 부모 경로·같은 구간의 **이미 정규화된 실제 영향**이다.
직전 약화 분석의 정규화 전 raw 목표가 아니므로 1을 넘을 수도 있다. 합계와 비율의 분모를
명시한다. 비율의 분모가 0이면 null이며 0%로 바꾸거나 그 시드를
삭제하지 않는다. 시드별 값·평균·표준편차와 질량을 합친 pooled 값을 구분한다. 계산 시드 간
표준편차는 동물 개체나 인간 참가자의 신뢰구간이 아니다. 점수 개선량을 정답률의 %p로
바꾸어 부르지 않는다.

비영 갱신에서 자기 점수와 기존 도움 합계가 각각 부모보다 `1e-8` 이상 나쁘지 않으면
`joint_nondegrading_updates`에 세고, 그중 하나 이상이 `1e-8`보다 더 크면
`joint_strict_improvement_updates`에도 센다. destination 개수만큼 중복하지 않는다.
관측 기반 방향이 기존보다 자기 수정과 도움을 모두 더 남겼다고 말하려면 두 지표를 따로
확인하고, 알려진 방해와 미관측 실제 방해도 함께 보고한다. 목적값 하나의 개선으로 두 지표의
동시 개선을 대신하지 않는다. 공유 참고는 안전 영역 밖일 수 있어 알려진 방해 위반이 허용되는
기술 대조다. 새 observed/oracle 후보는 위반이 0이어야 한다. 새 행동 성공 문턱, 통계적
유의성, 새 습득·일반화 판정을
추가하지 않는다. 이전 미지지를 새 기하 지표로 성공으로 바꾸지 않는다.

## 동결·자료·독립 검산·산출물

새 소스 16개(설정·프로토콜·소스·자동검사·독립 검산 포함)와 읽을 부모 파일 11개의 정확한
경로·SHA-256을 별도 등록에 고정한다. 부모는 완료된 약화 분석의 외부 등록·게시 증거·완료
검증, 내부 7개 결과 파일과 선택 억제의 저장 배열이다. 이전 부모 소스·자료 검증 체계도
선행 게이트로 재사용한다.
등록을 기존 비공개 원격에 게시하고 로컬과 동일한 원문 bytes를 확인한 게시 증거의 시간이
새 실제 집계 시작보다 앞서야 한다. 결과 경로는 새로 배타적으로 만든다.

- 설정: `configs/cone_frontier_v1.json`.
- 등록: `results/registration_cone_frontier_v1.json`.
- 게시 증거: `results/cone_frontier_publication_proof.json`.
- 배열·CSV·요약·메타데이터·등록 사본·해시: `results/cone_frontier_v1`.
- 독립 검산: `results/cone_frontier_v1/verification.json`.
- 검산을 통과한 값의 그림: `results/cone_frontier_figures_v1`.

최적화 결과는 같은 조건·시드·source·관측 부호·정보 조건·목적이 반복되면 재사용한다.
실제 유일한 최적화 case 수 C는 자료에서 결정하며 새 시행 수가 아니다. case key·단위
방향·투영·목적·목적지별 승수·제약·8개 증거 필드, 시행별 case index·영향·점수 변화·이동
길이·관측 상태·source·실제 g·완전 관측 표시는 총 **15개 배열**이다. 미관측 목적지의
패딩 제약·승수는 0이다. NoGo case index −1을 유효 case처럼 참조하지 않는다.

CSV는 배선→표현→후보→시드→관측 구간 순서의 `6×7×10×3=1,260`행이다.
24,000개 저장 시행에 대한 7후보는 168,000개 후보 시행 기록, 4목적지까지 펼치면
672,000개 점수 영향 셀이다. 새 학습·출력 갱신·내부 갱신·가치 갱신·난수·모델 생성 횟수는
모두 0으로 남긴다.

독립 검산은 새 producer를 import하지 않고 부모의 저장 특징·스칼라·관측 상태로 목적·제약·
실제 영향을 다시 구성하고 별도로 같은 최적화 문제도 푼다. 퇴화된 최적점의 방향 벡터가
우연히 다르더라도 목적·안전·증거로 판정하며 비유일한 벡터의 bytes 일치를 요구하지 않는다.
반환된 방향·투영·승수의 수치 최적성 증거, 목적과 정보의 분리,
점수 합계·구간·분모·출력 해시와 게시·실행 순서를 검사한다. 개발 검사는 작은 합성 원뿔만
쓰며, 실제 새 집계 결과를 보고 목적 가중치나 해석 문턱을 조정하지 않는다.

자동검사는 해가 알려진 직교·비스듬한·퇴화·반대 제약, 0 목적과 0 투영, 좌표 회전·제약 순서·
양의 배율에 대한 불변성, 직접 쓴 쌍대 증거와 임의의 안전 비교 방향의 상한, 입력 비변경,
잘못된 차원·비유한값·수치 설정의 거부를 포함한다.

## 결론의 경계

네 알려진 인공 전체 문자열의 저장된 출력 학습(Level 2)을 분석한다. 고정 내부 시냅스·입력
활성, 실제 바뀐 출력 계수, 별도 획득 보상 부호 기억, 이번에 계산한 대안 방향을 구분한다.
대안 방향은 실제 적용한 새 출력 가중치가 아니다. 이 계산 규칙을 초파리 생물학적 가소성으로
해석하지 않는다.

이름표 입력·보상 기억은 실제 LC11 시각 수량 회로나 수학 기호 이해가 아니다. 계산 시드는
동물이나 인간이 아니다. 새 문자열 일반화(Level 3), 인간 행동 유사성(Level 4), 공통 신경
기작(Level 5), 교육 효과를 추가 주장하지 않는다. 기존 인간 비교의 미지지와 맥락별 공동
습득·간섭·순서·일반화의 닫힌 선행 게이트를 유지한다.

결과가 유망해도 실제 학습의 개선은 별도 전향적 계획·등록·정보 및 자원 대조를 갖춘 새 실험이
필요하다. 이번 요청에서는 새 학습·예산 연장·시드 교체·가중치 탐색을 수행하지 않는다.
