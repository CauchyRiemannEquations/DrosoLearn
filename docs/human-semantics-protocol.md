# 인간 기록의 코드 의미와 원본 변환을 확인하는 계획

작성일: 2026-10-15 (Asia/Seoul). 이전의 자료 가용성 감사와 기록 연결 감사를 그대로 보존하는 후속 계획이다. 이미 원자료 구조와 일부 불일치를 보았으므로 탐색적 처리 감사로 분류한다. 눈가림 확증 사전등록, 인간 학습 성과 분석 또는 인간과 모델의 유사성 검정이 아니다.

## 먼저 쉽게 설명하면

두 기록에 같은 순서의 피드백이 있어도 한쪽의 숫자 `1`과 다른 쪽의 숫자 `1`이 같은 뜻이라는 보장은 없다. 화면의 왼쪽, 도형의 종류, 응답 버튼 번호가 서로 다른 코드일 수 있기 때문이다. 기대 보고도 답변 화면에 표시한 숫자와 저장 파일의 숫자가 다를 수 있다.

이번에는 숫자를 잘 맞게 바꾸는 규칙을 찾지 않는다. **원래 프로그램이 어떤 뜻으로 값을 저장했는지**의 근거를 찾고, 이미 정한 대응이 어느 코드 조합에서 어긋났는지 기록한다. 별도로 공개된 원본과 가공 파일을 비교할 때도, 원본을 결과에 맞춰 고치는 대신 문서화된 변환을 다시 실행해 같은 값이 나오는지 확인한다.

## 두 작업의 범위와 의존 관계

| 작업 | 이번에 확인할 내용 | 이 단계에서 허용하지 않는 결론 |
|---|---|---|
| A: OpenNeuro 코드 의미 감사 | 기존 피드백 연결 후보에서 선택·기대 코드의 고정 교차표, 원 응답·과제·추출 코드의 변환 근거 | 코드 불일치가 사람의 오답·기억 실패·원자료 오류라는 주장, 더 잘 맞는 변환의 사후 채택 |
| B: 공식 OSF 원본과 pybefit 가공 CSV의 변환 감사 | 파일별 권한과 버전, 원 변수·행·시행 대응, 근거가 있는 변환의 전 값 재현 | 원본과 가공 자료가 같은 독립 표본이라는 주장, 보상률·정답률·학습 곡선·모형 적합 |

A에서 의미를 확인하지 못한 값은 미해결로 남긴다. 그 값에 의존하는 인간 학습 지표와 사람/모델 비교는 보류한다. A의 미해결이 별도 자료인 B의 원본 무결성·변환 검증까지 막지는 않는다. B가 통과해도 A의 불일치가 해결된 것은 아니다.

새 참가자 모집, 저자에게 연락, 추가 개인정보 결합, 비공개 자료 접근은 이번 범위가 아니다. 허용된 정상 공개 경로와 기존 자료만 사용한다. 실제 실행 전에 자료·설정·코드·테스트·이 문서의 해시와 Git 버전을 고정한다. 실행 대상이나 변환 근거를 추가하면 추가 전후 범위와 해시를 따로 남긴다.

## A-1. 이전 결과를 그대로 사용하는 고정 교차표

이전 [기록 연결 결과](human-trial-linkage-findings.md)의 양방향 유일 피드백 후보와 엄격 비교 상태를 바꾸지 않는다. 대응 후보 23쌍의 12,880개 피드백 위치 중 엄격 비교가 가능한 12,334개를 코드 표의 고정 분모로 사용한다. 나머지 546개는 원값·위치·보류 사유를 보존하고 표에 채워 넣지 않는다. 새 파서로 원 사건을 다시 묶어 분모를 바꾸는 작업은 이번 A-1에 포함하지 않는다.

원 근거는 고정된 `corroboration.csv`, `linkage-report.json`, 원행 구간 기록과 등록 해시다. 이들 파일과 대응하는 원자료의 무결성을 먼저 확인한다. 결과에 맞는 참가자·과제·위치만 추리지 않는다.

| 표 | 고정 행 | 고정 열 | 고정한 일치 진단 |
|---|---|---|---|
| 기대 코드 4×4 | 사건 평정 `0, 1, 2, 3`에 이미 `+3`을 적용한 `3, 4, 5, 6` | MAT 원 코드 `3, 4, 5, 6` | `MAT = 사건 평정 + 3` |
| 선택 코드 2×2 | 사건의 화면 왼쪽·오른쪽 | MAT action `1, 2` | `왼쪽→1`, `오른쪽→2` |

표의 모든 칸을 명시하며 0개인 칸도 생략하지 않는다. 전체 표와 사전에 고정한 각 기록쌍의 REW/PUN 두 조건별 표를 모두 남긴다. 기록쌍·조건별 표의 합은 전체 표와 같아야 한다. 행·열 코드의 범례를 유지하고 빈칸을 ‘정답 없음’으로 표시하지 않는다.

입력 CSV의 `event_expectation_plus3`는 이전 감사에서 이미 고정 변환한 코드다. 여기에 3을 다시 더하지 않는다. 표의 행·열은 작은 코드부터 고정하고, 기록쌍·과제별 표도 같은 순서를 사용한다. `event_label`, `mat_row`, `task`, `feedback_ordinal`의 키는 유일해야 하며 각 기록쌍의 두 과제에서 관측 순번은 1부터 연속이어야 한다. 근거 없이 빠진 위치를 만들거나 순번을 다시 매기지 않는다.

기존 고정 기대 대응의 일치 8,199개와 불일치 4,135개, 선택 대응의 일치 6,220개와 불일치 6,114개를 재집계 검산의 기준으로 사용한다. 각각의 합은 12,334다. 이 기준을 확인하는 것은 코드 처리의 검산이지 새로운 인간 행동 결과를 발견했다는 뜻이 아니다.

허용되는 계산은 칸별 개수, 전체·조건별 합계, 정해진 대응의 일치·불일치 개수와 원행 추적이다. 정확도·보상률·확신의 평균·시행별 곡선·반전 전후 변화·상관·유의성 검정은 계산하지 않는다. 표에서 비율을 보고 ‘거의 무작위’, ‘특정 전략’, ‘인지적 혼동’ 같은 행동 설명을 만들지 않는다.

행·열 순열, 좌우 반전, 기대 offset, 일부 시점의 이동 또는 가장 잘 맞는 대응을 탐색해 선택하지 않는다. 특정 칸이 많다는 사실은 원 프로그램의 코드 정의를 대신하지 않는다. 다른 변환이 원 저자 근거로 확인되면 A-1의 결과는 그대로 남기고 A-2의 별도 근거와 후속 버전으로 제시한다.

## A-2. 어떤 근거가 있어야 코드 의미를 확정할 수 있는가

근거마다 정확한 파일·버전·SHA-256·위치·입력과 출력 변수·적용 범위를 기록한다. 고정 Git URL이 실제 코드가 아니라 포인터를 가리키면 실제 payload의 해시와 줄 번호를 구분한다. 내려받은 코드를 읽었다는 사실과 그 코드를 실행했다는 사실도 구분한다.

| 확인 대상 | 필요한 근거 | 그것만으로 부족한 근거 |
|---|---|---|
| MAT action의 뜻 | 원 로그 또는 추출·과제 코드에서 응답 키/좌우/도형을 MAT action으로 저장하는 명시적 대입과 변수 정의 | 행동값 배열의 인덱스로 `1/2`를 사용한다는 사실, 교차표의 일치가 많다는 사실 |
| 기대 코드의 뜻 | 기대 질문의 선택지·입력 키·원 응답·저장 코드 사이의 명시적 변환, 필요한 경우 시간 또는 과제 조건 분기 | MAT 코드를 분석에서 확률처럼 변환했다는 사실, 사후에 더 잘 맞는 순열 |
| 원 시행과 MAT 위치 | 연습·미응답·제외·과제 재시작을 처리하는 추출 규칙, 원 시행 키와 저장 위치의 추적 | 전체 피드백이 같다는 사실, 관측 피드백 순번이 연속이라는 사실 |
| 도형과 화면 위치 | 매 시행의 도형 ID와 위치 또는 이를 재현할 원 과제 로그·저장 규칙 | 좌우 응답 코드, 논문에 도형 종류가 설명되어 있다는 사실 |
| 반응 시간 | 측정 시작·종료 사건과 단위, 원 응답과 MAT RT를 잇는 추출 규칙 | 선택–피드백 간격, MAT에 RT 필드가 있다는 사실 |

변환이 조건·버전·응답키 종류에 따라 달라진다면 그 분기 조건 자체가 원 근거에 있어야 한다. 불일치가 있는 위치만 별도 취급하는 규칙을 결과에서 만들어내지 않는다. 원 코드를 실행할 필요가 생기면 의존성·부작용·입력·출력을 검토하고 별도 실행 범위를 고정한다. 이번 단계에서 원 MATLAB 모형을 실행하거나 RL 모형을 적합하지 않는다.

판정은 필드별로 `명시 근거 확인`, `근거는 있으나 적용 범위 미확정`, `미발견`, `서로 충돌`을 사용한다. 코드가 없으면 없다고 기록한다. 기존 고정 대응의 불일치 원인을 확정하지 못하면 `미해결`로 남긴다. 이를 분석 실패를 피하기 위한 새로운 제외 기준으로 바꾸지 않는다.

현재 [출처 확인 기록](human-semantics-source-review.md)에서는 고정 공개 tree의 183개 파일 경로에 과제 실행 파일·원 로그·새 추출 코드가 없었다. 이 목록의 부재를 다른 곳에도 코드가 존재하지 않는다는 뜻으로 확대하지 않는다. 보충 DOCX는 정상 다운로드가 HTTP 403이어서 본문을 확인하지 못했다. 포인터 목록 확인과 실제 payload 확보도 구분한다. 이런 접근 한계는 코드 의미를 확정할 근거를 얻은 것으로 세지 않는다.

원 의미가 문서로 확인되더라도 실제 값 전체의 정합성은 별도 문제다. 확인된 변환을 적용하는 후속 검산은 새 버전·설정·출력 경로로 진행한다. 기존 `+3`, 좌우→1/2 설정과 원 교차표를 수정하지 않는다.

## B-1. 공식 OSF 원본을 받을 수 있는 조건

이전 [권한 후속 기록](human-trial-permissions-followup.md)의 공개 메타데이터는 출처 탐색의 시작점이다. 공식 원본과 GitHub 가공 CSV의 동일성 또는 변환 관계를 이미 확인했다는 근거로 사용하지 않는다.

다운로드 전에 실제 데이터 component·폴더·개별 파일의 원 링크, 파일 ID, 버전 또는 개정 식별자, 제공 형식과 크기, 적용 라이선스와 예외를 확인한다. 프로젝트 전체의 선언과 개별 파일·제삼자 자료의 제한을 구분한다. 권한이 미확정인 원본은 저장소에 재배포하지 않는다. 검증용 외부 캐시에 둘 때에도 경로와 해시·접근 시각·사용 범위를 남긴다. 정상 공개 접근이 실패하면 실패 기록을 보존하고 다른 경로로 제한을 우회하지 않는다.

확보 시에는 받은 원바이트의 SHA-256을 계산한다. 서버가 알려 준 크기나 해시는 출처 메타데이터로 보존하며 직접 계산한 값과 구분한다. 압축 자료는 압축 파일과 실제 사용 구성 파일의 해시를 각각 남긴다. 원본은 읽기 전용으로 보존하며 가공 CSV와 별도 경로에 둔다. GitHub 가공본도 고정 커밋·파일·해시를 지정한다.

원본을 확보했더라도 참가자·조건·시행 키의 의미가 확인되지 않으면 행 순서나 파일명 숫자만으로 대응시키지 않는다. Main/Pilot 같은 변형, 반복 세션, 중복 기록을 구별한다. 기존에 발견한 중복 행을 자동으로 삭제하거나 독립 참가자로 다시 세지 않는다.

## B-2. 변환 재현을 실행할 수 있는 조건

변환 전 다음 항목을 고정한다.

1. **원 변수의 뜻:** 선택·실제 결과·유리한 선택 또는 정오·정보 요청·상태·결측의 구분과 원 코드 목록.
2. **관측 단위와 키:** 원본의 참가자·실험 변형·세션·시행 키, 가공 CSV의 행·열 위치로 가는 명시적 대응.
3. **변환 근거:** 원 저자 가공 코드 또는 완전한 규칙 문서, 정확한 버전, 원 변수에서 출력 변수까지의 추적.
4. **허용 연산:** 원 근거에 있는 축 전환·직렬화·코드 변환·결측 표기만 명시. 근거 없는 행 교환·열 이동·단위 변환·제외는 금지.
5. **검증 규칙:** 비교 대상 파일 전체, 차원·정렬·타입·코드·결측의 정확 대조, 불일치 기록 방식과 종료 기준.

논문의 일반적인 과제 설명만 있고 추출 코드나 완전한 규칙이 없으면, 무엇을 받아야 같은 CSV가 나오는지 확정할 수 없는 상태로 남긴다. 그 경우 파일 구조와 권한 감사까지만 진행한다. 원본과 가공본의 교차표를 보고 가장 잘 맞는 변환을 역으로 정하지 않는다.

정수형 선택·결과·상태·정오 코드는 정확한 값 비교를 사용한다. 결측은 결측끼리만 비교하며 `0`, 음수, 특별 코드 또는 정보 요청으로 바꾸지 않는다. 수치가 `1`과 `1.0`처럼 다르게 직렬화된 경우에는 사전에 명시한 자료형 규약에 따라 값의 동일성과 파일 바이트의 차이를 함께 기록한다. 소수형 변수가 실제 대상에 포함되면 비교 정밀도를 실행 전에 별도 고정하며, 결과를 본 뒤 허용오차를 늘리지 않는다.

이번 탐색에서는 공식 OSF의 `Main` 목록은 비어 있고 `Pilot` 목록에는 154개 항목이 있었다. 가공본 Main의 50행 중 25개는 공식 목록에서 파일명이 정확히 대응했으며, 가공본 Pilot의 24행은 대응이 없었다. 파일이 `Pilot` 폴더에 있다는 이유로 가공본의 Pilot 집단이라고 분류하지 않는다. 전체 Main 50행과 Pilot 24행의 가용성·대응 여부를 성과를 보기 전에 고정하고, 확보 가능한 Main 25행만 별도의 부분 감사 범위로 명시한다. 선정 근거는 파일명과 가용성이며 사람의 성적이 아니다.

부분 감사에서는 고정한 25개 전체의 모든 대상 값·결측·차원·키를 재현해야 한다. 모두 일치하더라도 통과 범위는 해당 25개 원본과 가공 행 사이의 변환뿐이다. 나머지 Main 25행과 Pilot 24행은 원본 미확보·미대응으로 보존한다. 전체 74행의 원본 계보, 개체 독립성 또는 인간 비교 준비가 통과한 것으로 확대하지 않는다. 기존 Pilot 중복 행도 임의로 삭제하지 않는다.

표본 일부만 맞는지 보는 검사가 아니라 고정 범위의 모든 파일·행·열·값·결측을 대조한다. 식별자, 차원, 순서, 중복 개수, 결측 마스크도 값과 함께 검증한다. 불일치는 원 위치·대응 위치·원값·재현값·가공값으로 추적하며, 일치시키기 위한 수정은 하지 않는다. 개인정보를 새로 추정하거나 연결하지 않는다.

## 후속으로 넘어가는 게이트

| 상태 | 다음에 허용되는 작업 | 계속 보류하는 작업 |
|---|---|---|
| A 교차표와 원본 해시 검산만 통과 | 불일치 칸의 원 코드 근거 조사 | 코드 변환의 확정, 관련 인간 지표·사람/모델 비교 |
| A 일부 필드의 명시 근거 확보 | 그 근거를 별도 버전에 고정하고 전체 값 변환 검산 계획 작성 | 근거가 없는 필드의 의미 추정, 기존 결과 덮어쓰기 |
| A 원인 미해결 | 미해결과 필요한 원 로그·코드를 보고; 독립적인 B 권한·원본 감사 진행 | A에 의존하는 행동 분석 |
| B 권한·버전·원본 무결성 확인 | 원 변수와 변환 근거의 정적 검토 | 근거 없는 재구성 또는 가공본으로 권한 자동 확장 |
| B 키·변환 근거까지 확인 | 고정 규칙으로 전체 변환 재현과 정확 대조 | 성과·학습 곡선·RL 모형·종간 비교 |
| B 전체 값·결측·차원 대조 통과 | 변환 계보가 확인된 범위를 보고하고 별도 행동 연구 계획 작성 | 곧바로 인간/모델 유사성 또는 동일 신경 기작 주장 |
| B 불일치 또는 대응 미확정 | 원인과 위치·가능 범위·추가 근거 필요를 보존 | 값 수정·사후 제외·미확인 대응을 이용한 종속 분석 |

게이트 통과는 자료 처리의 근거가 준비되었다는 뜻이다. 인간 학습 현상 자체를 확인했다는 뜻이 아니다. 일부 항목이 통과해도 나머지 항목은 별도 상태로 남긴다.

## 합성 테스트와 독립 검산의 관점

실제 사람 기록을 테스트 입력으로 쓰지 않는다. 다음 사례를 인공 자료로 검증한다.

- 4×4·2×2 고정 행·열과 0개인 칸, 전체·REW·PUN 표의 합, 고정 대응의 대각선과 비대각선 합.
- 불일치가 많은 자료에서도 행·열 순서와 `+3`, 좌우→1/2 설정이 바뀌지 않음.
- 엄격 비교 불가 행의 별도 보존, 새로운 결측·미지 코드·불리언·비정수 코드의 명시적 거부.
- 원 행과 MAT 위치의 추적, 입력 순서와 원본 불변, 파일 해시·설정·코드 변경 시 동결 거부, 기존 출력 보호.
- 원본과 가공본의 완전 일치, 한 값 차이, 한 결측 차이, 잘못된 축·순서·참가자 키·중복 개수.
- 정보 요청 등 추가 선택과 실제 보상·정오·상태의 구분, 결측을 `0`으로 잘못 채운 변환의 검출.
- 문서화되지 않은 순열이나 offset이 있으면 ‘가장 비슷한 변환’으로 자동 통과시키지 않음.
- 명시 근거가 있는 변환의 정확 재현과 근거·파일·버전·권한이 빠진 경우의 게이트 차단.

독립 검산은 주 집계·변환 함수를 호출하지 않고 고정 원본과 산출물에서 표의 모든 칸, 대상 행과 제외 사유, 변환의 전체 값·결측·순서·차원을 다시 확인한다. 형식과 값의 동일성을 혼동하지 않으며 불일치·접근 실패·미해결을 지우지 않는다.

## 산출물과 해석의 종료선

새 결과에는 조사한 근거 목록, 파일별 버전·권한·해시, A의 고정 교차표와 원행 진단, 필드별 의미 확인 상태, B의 원본·가공본 대응과 변환 검산 또는 실행 보류 이유, 독립 검산, 쉬운 설명을 남긴다. 확인하지 못한 근거는 확인하지 못했다고 적는다. 원 저자의 분석 전체를 재현했다고 부르지 않는다.

기존 DrosoMem과 DrosoLearn의 완료 원본·설정·등록·실패·결과는 변경하지 않는다. 이번 준비 작업으로 Level 4 또는 Level 5, 인간 수학 학습이나 교육적 효과를 주장하지 않는다. 행동 지표와 비교 가설은 의미와 변환의 필요한 게이트가 충족된 범위에서만 다음 프로토콜로 사전에 정의한다.
